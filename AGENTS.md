# OPCLook — правила для агентов

Этот файл — абсолютные правила. Он важнее любых других инструкций в репозитории.

## Начало каждой сессии
1. Прочитать `docs/status.md` (текущая работа, блокеры), затем свою задачу
   в `docs/audit-2026-10-27.md` (id вида `U2`, `D1`, `A5`) и нужные модули.
2. Не останавливаться с вопросами, если решение не входит в список
   «Спросить человека». Для неописанного поведения выбрать то, чего ждёт
   инженер АСУ ТП от OPC-клиента, и записать выбор в `docs/devlog.md`.
3. Для обновления получения данных OPC UA/DA открыть
   [входную routing table для LLM](docs/llm-update-routing.md). Сначала проверить
   готовые библиотеки и владельцев механизмов (R2.0), затем выбрать маршрут,
   контракт и тесты. Не дублировать SDK Publish/recovery или COM lifecycle.

## Never crash (для каждой новой и изменённой строки)
- Никаких `unwrap`/`expect`/`panic!`/`todo!`/`unreachable!`/`unimplemented!`
  вне тестов. Вместо них `?`, `ok_or(..)?`, `let … else`, `if let`.
  Исключение — доказуемо безошибочный случай: `.expect("почему не упадёт")`.
- Ответы серверов OPC, файлы CSV/настроек — враждебный вход: `get()` вместо
  `[i]`, `checked_*`/`saturating_*`, ограниченные аллокации и рекурсия.
- `unsafe` только в COM/WinAPI-обвязке (`crates/backend/src/bff/da.rs`, `crates/backend/src/bff/da_variant.rs`, `crates/backend/src/bff/com.rs`,
  `crates/backend/src/net/windows.rs`, `crates/backend/src/winutil.rs`, `crates/backend/src/bff/net.rs`, `crates/backend/src/bff/mdns.rs`, `src/da_route.rs`,
  `nethelper/`), каждый блок с `// SAFETY:`.
- Отравленный lock не фатален: `lock().unwrap_or_else(PoisonError::into_inner)`.
- Каждый фикс бага приходит с регрессионным тестом, который падал до фикса.

## Не обсуждается
- UI не знает протоколов: только `Command`/`Event` (`crates/contract/src/model.rs`).
- UA и DA используют готовые нативные клиентские библиотеки; windows-rs и
  generated COM bindings сами по себе не являются OPC-клиентом. Смена кандидата
  разрешена владельцем. Не дописывать свой OPC data-plane ради пробелов SDK:
  [обязательный результат и миграция](docs/native-backend-migration.md).
- Ни одна сессия не может заблокировать другие сессии.
- Все видимые пользователю строки — в `crates/locale/src/lib.rs` (RU/EN/ZH), без хардкода
  в `src/ui/**` и `src/app/**` (`tests/no_hardcoded_ui_strings.rs`).
- Ничего не теряется молча: ошибка видна пользователю (журнал или диалог),
  `eprintln!` в release-сборке невидим и не считается сообщением.
- Одна задача — один коммит с id: `U2: check monitored item status codes`.
  Только зелёные состояния (см. гейты).

## Гейты перед каждым коммитом
- `cargo fmt --all -- --check`.
- Целевая сборка — только `i686-pc-windows-msvc` (CI:
  `.github/workflows/windows-x86.yml`). Если Windows-тулчейна нет (облачная
  Linux-среда), изменённый код проверяется Linux-стендом вне репозитория:
  отдельный крейт подключает **настоящие** файлы через `#[path = ...]`, а
  Windows-зависимости заменены заглушками; стенд компилируется и гоняет
  тесты. Что проверить так нельзя (COM, WinAPI), помечается в коммите и
  в `docs/status.md` как «не скомпилировано, проверит CI».

## Проверка результата
- UI-изменение проверяется headless через `egui_kittest` (клик, двойной клик,
  disabled) и рендером в PNG, который агент сам смотрит.
- Сетевое поведение UA — против живого sample-сервера `async-opcua`
  (`ServerBuilder::new_sample()`), где это возможно.

## Параллельные агенты
- Свой `git worktree`, своя ветка и `CARGO_TARGET_DIR` на агента.
- Один владелец на файл (список — в задаче агента). Чужие файлы — только
  точечные правки, явно разрешённые в задаче; перечитать перед правкой.
- Новые ключи `Tr` — только в своей секции `i18n.rs` (якорь указан в задаче),
  во всех трёх языках.

## Спросить человека только о
- лицензиях вне MIT/Apache-2.0/BSD, тратах, публикации/push, персональных
  данных, разрушающих git-операциях; обо всём, что этот файл оставляет
  неясным (сомневаешься — не добавляй).

## Перед завершением
- Обновить `docs/status.md` (что сделано, что осталось, что не проверено),
  `docs/devlog.md` (что закрыто, цифры, что открыто), статус пункта в
  `docs/audit-2026-10-27.md`.
- Честные цифры: каждое число помечено как измеренное или оценённое;
  заглушка или частично подключённая настройка не считается сделанной.
