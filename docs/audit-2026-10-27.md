# Аудит OPCLook: баги, кривые реализации, UI/UX

## R2.1 — начальные снимки и резервирование (частично, 2026-10-30)

Engine владеет потребностью начального снимка и резервирует Read permit;
GUI больше не отправляет свой Add snapshot напрямую. Есть ограничение ledger
ItemKey и запрет reuse в эпохе, обработка раннего terminal push и сохранение
legacy fallback. Проверяемый scope и открытые WriteReadback/конфиг/DA/gap — в
status; полная реализация R2 и весь набор таблиц не заявляются завершёнными.

## R2.1 — частичное исправление гонки Read (2026-10-30)

Ответ или ошибка одного из нескольких уже отправленных Read не освобождают
флаг опроса, пока в Engine остаётся другой Read. Регрессия вызывает send,
accept и due; до исправления воспроизведён лишний Read. Это не гарантия одного
слота: параллельные прямые отправки пока возможны. Очередь потребностей,
остальные R2-проверки и миграция DA открыты; см. status и devlog.

## R2.ROUTE — пробелы Foundation и reuse библиотек (2026-10-30)

Прямое требование владельца: [native SDK UA/DA](native-backend-migration.md),
с разрешённой сменой кандидата; свой OPC data-plane подлежит замене.

Статус: документированы [OF01–OF12](opc-foundation-gap-review.md), runtime открыт.
[Routing table](llm-update-routing.md) направляет обновления через R2.0:
[владелец SDK/adapter/Engine/UI](backend-ownership.md) проверяется до нового кода.
В старом плане исправлен C06: Subscription + Sync Read определяется capability,
а не ограничением UI другого продукта. Queue=1 не обещает полную историю,
snapshot не скрывает gap, небадовый Write не всегда полное подтверждение.

O01–O35 задают новые ожидаемые проверки. Точный locked SDK recovery, полная
DA 2/3 спецификация и Windows COM/live не проверены. Только документация;
Cargo/rustfmt отсутствуют, fmt/сборки/продуктовые тесты не запускались.

## R2.TEST — контракт тестов и настройки соединения UA/DA (2026-10-30)

Статус: [нормативные таблицы](testing/acquisition-truth-tables.md) подготовлены,
