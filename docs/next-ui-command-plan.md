# План следующей работы: тема, действия и интерфейс

Этот документ сохраняет постановку следующей работы; текущие результаты P1 и ограничения описаны в [отчёте](reports/p1-theme-validation.md). Базовая работа A–H и B1–B20 уже реализована; Rust 1.99.1 остаётся базой. Не откатывать её и не менять исторические `docs/screenshots/baseline-f/`, `docs/screenshots/after-h/` и [отчёт измерений](reports/refactor-frame-baseline.md). Перед началом перечитать `AGENTS.md`, статус, аудит и фактический код на текущем HEAD.

## Основания и границы

На базовом коммите до P1 `Theme::{System, Light, Dark}` в `src/settings.rs` сохранялась в настройках, по умолчанию System; старые файлы настроек совместимы. Три варианта уже были в диалоге настроек. `src/ui/style.rs` настраивает обе `Visuals`, System следует теме ОС и при отсутствии сведений использует тёмную; `src/ui/colors.rs` выбирает семантические цвета по флагу текущего кадра. До P1 прямого переключателя в верхней панели `src/ui/menu.rs` не было; после P1 он добавлен. Обычный текст имеет размер 13 pt: его нельзя считать крупным; прежняя проверка 3:1 на белом не доказывала читаемости на фактических фонах. Измерения P1 приведены в [отчёте](reports/p1-theme-validation.md).

Исследованные источники — ориентиры, а не готовое решение OPCLook:

- [WordCraft engine, фиксированная версия](https://github.com/storytold/wordcraft/blob/3de6ff95af86c19d67030cd96dba15cd6a45a25e/crates/engine/src/lib.rs): каталог `CommandSpec` с текстовым ID, метаданными, доступностью и исполнением; `Session::run` объединяет вызовы UI, CLI, control и MCP. [Keymap](https://github.com/storytold/wordcraft/blob/3de6ff95af86c19d67030cd96dba15cd6a45a25e/crates/engine/src/keymap.rs) нормализует переносимый Mod, проверяет известные ID, ограничения и переопределения. [Обработка клавиш UI](https://github.com/storytold/wordcraft/blob/3de6ff95af86c19d67030cd96dba15cd6a45a25e/crates/ui-egui/src/keys/shortcuts.rs) переводит клавиши в keymap и `app.run`, отдельно оставляя `ui.*` и защищая фокус/модальные окна.
- GridCraft на версии `43284377d2466037628e57d8ad0c891778fdb45c`: [Архитектура](https://github.com/storytold/gridcraft/blob/43284377d2466037628e57d8ad0c891778fdb45c/docs/architecture.md) описывает общий путь `Session::execute`; [cmd.rs](https://github.com/storytold/gridcraft/blob/43284377d2466037628e57d8ad0c891778fdb45c/crates/engine/src/cmd.rs) содержит каталог и информацию о доступности. Также есть токены обеих тем, тесты контраста и компоненты с отдельными ответами. Не переносить предположения об undo или откате: OPC-запись нельзя считать обратимой.
- [craft-libs UI](https://github.com/storytold/craft-libs/blob/b4afa6d22ae41bd36524c32dbcab3ff257ae4cdd/crates/ui/README.md) и его [аудит компонентов](https://github.com/storytold/craft-libs/blob/b4afa6d22ae41bd36524c32dbcab3ff257ae4cdd/docs/ui-components-audit.md): небольшие стилизованные кнопки, вкладки и элементы разметки возвращают egui Response; состояние, диспетчеризация, стиль, ресурсы и локализация остаются у приложения. Стабильные ID не зависят от переведённых подписей. WordCraft использует взаимодействие ribbon tab, другие приложения адаптируют виджеты. Версия зафиксирована; сведения проверены 28 октября 2026 года.

- [craft-keymap](https://github.com/storytold/craft-libs/blob/b4afa6d22ae41bd36524c32dbcab3ff257ae4cdd/crates/keymap/README.md) предоставляет независимую от UI логику команд, привязок, областей действия, конфликтов, переопределений и ограничений; egui и UI с craft-ui/craft-i18n подключаются опционально. Каталог приложения, диспетчеризация и файловые диалоги остаются у приложения. Различия раскладок и физических клавиш в исправленном egui suite требуют проверки; готовая совместимость не доказана.

Источники не обосновывают универсальную асинхронную EventBus или числовые номера команд. Числовые коды ниже — наше предложение по запросу пользователя. Не копировать фреймворк целиком и не добавлять зависимость craft UI сейчас; перед возможным заимствованием проверить совместимость с crates.io egui 0.37 в OPCLook и зависимость кандидата от расширений форка ArtCraft.

## Фазы реализации

### P1 — палитры и выбор темы в заголовке

Владелец: один исполнитель; основные файлы `src/ui/style.rs`, `src/ui/colors.rs`, `src/ui/menu.rs`, `src/settings.rs`, `crates/locale/src/lib.rs`, `tests/ui_polish_theme.rs`, снимки и документация. Зависимость: текущий HEAD.

- [x] Определить единые токены поверхностей, текста, полос строк, выделения, границ, hover, focus, disabled и семантических состояний для обеих тем. Для Light предложить мягкие слегка более тёмные поверхности с тёмным текстом; для Dark — угольные поверхности со светлым текстом. Не затемнять весь текст одинаково. Проверить и явно заданные цвета в таблице, журнале и других видимых областях.
- [x] Измерять контраст фактических пар foreground/background, включая композицию прозрачности и состояния поверх разных поверхностей. Инженерные цели: 4.5:1 для обычного текста, 3:1 для крупного текста и границ элементов/индикатора фокуса; это не заявление о сертификации WCAG. Ориентиры: [контраст текста WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) и [контраст нетекстовых элементов](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html); не округлять 4.499 до проходного 4.5. Disabled остаётся различимым, а критическая информация не передаётся только таким текстом или цветом.
- [x] Добавить в верхнюю панель явный доступный выбор System/Light/Dark, локализованный на RU/EN/ZH. Использовать существующее поле и механизм сохранения, показывать ошибки сохранения, согласовать открытый черновик настроек с изменением из заголовка. Изменение применяется сразу; System реагирует на изменения ОС, а при отсутствии сигнала использует тёмную тему. Проверить загрузку старого JSON и сохранение после перезапуска.
- [x] Headless: реальные клики по каждому варианту, активная тема, смена ОС в System, fallback, принудительная тема, сохранение и старая конфигурация. Проверить видимость и доступность на узком окне. Сформировать и самостоятельно посмотреть PNG Light/Dark/System с RU/EN/ZH, заголовком, таблицей, журналом, выбранными, hover и focus состояниями; отдельно проверить измеренные реальные пары контраста.

### P2 — каталог действий и первый вертикальный срез

Текущее состояние: частичная реализация трёх действий, в том числе защищённого пути записи. Этап остаётся открытым: совместимые границы размеров payload и ранняя проверка формы действия остаются открыты, Windows i686 ожидает CI. Известные credentials маскируются; обнаружение неизвестных секретов в произвольных ответах не обещается. Отмена до отправки исключает запись; уже отправленную OPC-запись отменить не обещаем. Подробности — в [статусе](status.md) и [журнале](devlog.md).

Владелец: один исполнитель; обследовать `src/ui/menu.rs`, `src/ui/shortcuts.rs`, `src/app/`, `crates/contract/`, `crates/engine/` и CLI. Зависимость: P1 завершена. Начать с одного безопасного представительного действия, например открытия подключения Ctrl+N или обновления F5, после проверки его фактической семантики.

- [ ] Спроектировать общий каталог действий над существующими типизированными `Command`/`Event` и Engine, не заменяя транспорт и не превращая внутренние параметры в строки. Стабильный семантический ID и явный стабильный числовой код — отдельные поля; не использовать индекс `Vec` или порядок discriminant, не переиспользовать выведенные из обращения коды. `RequestId` остаётся отдельным идентификатором корреляции. Добавить тесты уникальности ID и кодов, совместимости и запрета повторного использования выведенных кодов.
- [ ] Предлагаемое распределение: общие типизированные ID действий, payload и переносимые метаданные — в contract; исполнение доменных действий и их доступность — в Engine. GUI-действия `ui.*` остаются локальными в предлагаемом `src/app/actions.rs`, а адаптер дескрипторов — только в UI. Настройки GUI не переносить в Engine; backend `Command`/`Event` не менять.
- [ ] Описать типизированную полезную нагрузку, проверку параметров, доступность и локализуемую причину недоступности. Меню, панели и клавиатура вызывают единый путь исполнения; CLI использует его только для действий, допустимых без GUI. `ui.*` остаются GUI-действиями, Engine и контракт не зависят от egui. Сохранить совместимость существующих CLI-флагов.
- [ ] Сначала доказать эквивалентность одного среза кнопка/меню/клавиша и отсутствие побочных эффектов при проверке доступности. Затем подключать записи: сохранить имеющиеся подтверждения и безопасность, исключить повтор записи при автоповторе клавиши или повторных проходах кадра, не делать автоматический retry записи; предусмотреть ограничения, отмену и маскирование секретов в диагностике.

### P3 — переносимые сочетания

Владелец: один исполнитель; `src/ui/shortcuts.rs`, каталог действий и соответствующие тесты. Зависимость: P2, первый срез.

- [ ] Получать стандартные сочетания из каталога, нормализовать Mod для платформ, выявлять конфликты и не исполнять одно событие дважды. Защитить поля ввода, фокус, модальные окна и IME; проверить Enter и уже существующие пользовательские сценарии.
- [ ] Базовые привязки обязательны. Сравнить независимое ядро craft-keymap с небольшим собственным адаптером: проверить двойную лицензию MIT/Apache, совместимость с crates.io egui 0.37 в OPCLook и зависимость кандидата от расширений форка ArtCraft, физические клавиши и раскладки; проверить, что выбранные optional features не подтягивают графические зависимости в чистое ядро. Сейчас зависимость не добавлять; при возможном принятии закрепить неизменяемую версию.
- [ ] Пользовательский редактор необязателен. При необходимости добавить ограниченные пользовательские переопределения с проверкой известных ID, конфликтов и размеров входа; не ломать старые настройки. Отображать действующее сочетание, а не вручную заданную строку.

### P4 — палитра команд

Владелец: один исполнитель; GUI и локализация, с использованием P2–P3. Зависимость: каталог и keymap для первого набора действий.

- [ ] Поиск по локализованному названию, стабильному ID и номеру; показывать актуальное сочетание, доступность и причину недоступности. Поиск и вычисление доступности не выполняют действия. Вызов проходит через тот же путь и подтверждения, что меню и клавиатура.
- [ ] Проверить выбор, отсутствие результатов, недоступные команды, фокус, Enter и повторное нажатие в headless UI на трёх языках.

### P5 — небольшие локальные компоненты

Владелец: один исполнитель; точечные изменения `src/ui/` и тестов. Зависимость: принятые токены P1; выполнять постепенно вместе с P2–P4.

- [ ] Выделять только повторяющиеся компоненты с интерфейсом `show(model, style) -> Response` или типизированным действием. Стабильные ID не зависят от перевода; стиль берётся из токенов. Компоненты не владеют `App` и не обращаются к backend.
- [ ] Отдельный `ui-egui` crate — необязательный шаг только при доказанной пользе; обычные зависимости — Engine/contract/locale. Не создавать инфраструктуру ради самой инфраструктуры.
