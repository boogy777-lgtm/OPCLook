# План: OPC UA поиск, вложенные endpoints и сетевые настройки

**Статус:** частично реализовано (2026-10-26). Реализованы: отказ от
`AdapterSelection::Auto`/fallback, один ComboBox адаптера, loopback без
адаптера, блокировка удалённых операций без адаптера, счётчик `UA-сессии:
N/100`, union endpoints сканером по `ApplicationUri`. Не реализованы
(вне текущего объёма network-binding): вложенный список сервер/endpoint,
немедленный merge `UaScanFound` в UI и удаление буферов.
**Проект:** `opcda-egui`

## 1. Термины

- **OPC UA сервер** — одно приложение, идентифицируемое `ApplicationUri`.
- **Endpoint** — URL + security policy/mode внутри сервера.
- **Loopback** — локальный виртуальный интерфейс `127.0.0.1`/`::1`.
- **Локальный IP** — адрес сетевого адаптера (`192.168.2.1`, `172.28.76.90` и т.п.).
- **LDS не требуется.**

Пример:

```text
Один сервер (ApplicationUri):
  opc.tcp://NTBK700582:4840
  opc.tcp://127.0.0.1:4840
```

Это **не два сервера**, а два endpoint одного сервера. `NTBK700582` — имя ПК, `127.0.0.1` — loopback. Оба URL ведут на один OPC UA сервер.

## 3. OPC UA: layout

```text
Адрес: [NTBK700582........]  Порт: [4840]
URL:   [opc.tcp://NTBK700582:4840................]

[Поиск в сети]  [Поиск через LDS/mDNS]
```

Поведение:

- `host + port` — механизм ручного поиска.
- URL — поле для прямого подключения/выбранного endpoint.
- Кнопка «Поиск» удаляется.
- «Поиск в сети»:
  - `host` заполнен → ищется только этот host:port;
  - `host` пуст → loopback + локальные адреса + подсеть.
- «Поиск через LDS/mDNS» остаётся отдельной кнопкой, но не является обязательным.
- При вводе host/port и запуске поиска URL обновляется на `opc.tcp://host:port`.
- Выбор endpoint в результатах заполняет URL.
- Двойной клик по endpoint подключается с текущими security/identity настройками.

## 4. OPC UA: результаты

Заголовок остаётся:

```text
Найденные серверы:
```

Отображение:

```text
▾ CODESYS Control Win V3 x64 — urn:...
    opc.tcp://NTBK700582:4840 | None / None
    opc.tcp://127.0.0.1:4840  | None / None

▾ Второй сервер — urn:...
    opc.tcp://...
```

Правила:

- Сервер — `CollapsingHeader`.
- Endpoint — вложенная строка.
- По умолчанию сервер раскрыт.
- Пользователь может свернуть.
- Новый поиск создаёт новый набор результатов и снова раскрывает серверы.
- Для стабильности ID использовать `ApplicationUri` + epoch результатов.
- Клик по endpoint выбирает URL.
- Двойной клик — подключение.
- Счётчик/сортировка — по серверам, не по endpoint.
- Заголовок «Найденные серверы» не переименовывать.

## 5. Немедленное отображение

Сейчас результаты сканера копятся в `ua_scan_servers`, а LDS-результаты могут не попадать в `ua_search_results`.

Исправить:

- `UaScanFound` сразу мержит сервер в `ua_search_results`.
- `UaNetworkFound` сразу мержит сервер.
- `UaServersFound` (ручной host) сразу обновляет список.
- После каждого merge вызывать `refresh_ua_combos`.
- `UaScanFinished` только завершает прогресс/показывает ошибку.
- Удалить буферы:
  - `ua_scan_servers`;
  - `ua_network_results`;
  - `ua_auto_pending`.

## 6. Дедупликация endpoints

Ключ сервера:

1. `ApplicationUri`, если не пустой.
2. Иначе первый endpoint URL.

При совпадении ключа:

- не отбрасывать новый результат;
- объединять `endpoints`;
- дедуплицировать endpoint по нормализованному URL;
- сохранять policy/mode каждого endpoint;
- не терять `NTBK700582` при находке через `127.0.0.1`;
- не терять `127.0.0.1` при находке через `NTBK700582`.

Ожидаемый результат для текущего стенда:

```text
1 сервер
  2 endpoint: NTBK700582:4840, 127.0.0.1:4840
```

## 7. Сканер

LDS не использовать как обязательный источник.

Цели при пустом host:

1. `127.0.0.1:4840`;
2. `::1:4840`;
3. локальный IP выбранного адаптера;
4. адреса подсети.

Для каждой цели:

- TCP precheck;
- прямой `GetEndpoints`;
- сохранить **все** endpoint descriptions;
- не брать только `endpoints.first()`;
- не отбрасывать сервер при совпадении одного URL;
- объединять endpoint’ы по `ApplicationUri`.

`FindServers`/LDS можно оставить только как необязательный дополнительный источник для отдельной кнопки LDS/mDNS, но не для основного сканера.

## 8. Сетевые настройки

Удалить:

- кнопку **«Автоматически»**;
- `AdapterSelection::Auto`;
- fallback на физический адаптер;
- автоматический выбор IP.

Семантика:

```text
None            = адаптер не выбран
Adapter(id)     = выбран конкретный адаптер
```

UI:

```text
Сетевой адаптер: [ Wi-Fi (Intel Wi-Fi 6E AX211) ▼ ]  [Обновить]

Состояние: Работает
Адреса: 172.28.76.90/24
Шлюз: ...
Метрика: ...
Локальный IP: [ 172.28.76.90 ▼ ]
```

Правила:

- выбран ровно один адаптер;
- детали показываются только для выбранного;
- длинные описания/адреса переносятся;
- ширина ограничена `ui.available_width()`;
- окно не расширяется;
- при выборе адаптера сразу сохраняется конкретный локальный IP;
- если адаптер пропал/выключен — ошибка и требование выбрать другой;
- без выбранного адаптера:
  - loopback-поиск/подключение разрешены;
  - non-loopback поиск/подключение и подсеть — ошибка «Выберите сетевой адаптер».

## 9. Модель и миграция

- `AdapterSelection::{None, Adapter(AdapterId)}`.
- `NetworkInventory::resolve`:
  - `None` → `Err(NetError::NoAdapterSelected)`;
  - адаптер найден и usable → lease;
  - нет/down → ошибка, без fallback.
- Удалить `FallbackReason` и fallback-поля, если они больше не используются.
- Старые настройки:
  - валидный GUID сохранённого адаптера — использовать;
  - пустой/невалидный/отсутствующий GUID — «не выбран»;
  - пользователь выбирает адаптер заново.
- `selected_local_ip` хранить как конкретный IP, не как Auto.

## 11. Тесты

### UI

- Заголовок «Найденные серверы» присутствует.
- Один сервер с двумя endpoint отображается как один раскрытый сервер + две вложенные строки.
- Оба URL видны сразу.
- Сворачивание работает.
- Новый поиск снова раскрывает серверы.
- Кнопки «Поиск» нет.
- `host + port` и URL находятся на разных строках.
- Заполненный host запускает ручной поиск.
- Пустой host запускает loopback+subnet.
- В сетевых настройках нет Auto.
- Выбран ровно один адаптер.
- Окно не расширяется за границы.
- Без адаптера remote-поиск/подключение блокируются.

### Scanner

- `GetEndpoints` возвращает все endpoint, не только первый.
- Один `ApplicationUri` из двух адресов → один сервер, union endpoint.
- `NTBK700582` и `127.0.0.1` не теряются.
- LDS отсутствует — поиск работает.
- `UaScanFound` обновляет UI до `UaScanFinished`.

## 12. Критерии готовности

- Нет кнопки «Поиск».
- `host + port` сохранены, URL на следующей строке.
- «Поиск в сети» работает и для ручного host, и для пустого host.
- LDS не требуется.
- `127.0.0.1:4840` даёт сервер со всеми endpoint, включая `NTBK700582` и loopback.
- Результаты появляются сразу.
- Заголовок «Найденные серверы» не изменён.
- Серверы раскрыты по умолчанию.
- В сетевых настройках нельзя выбрать Auto.
- Выбран ровно один адаптер, список не выезжает.
- Старые настройки не ломаются, но требуют явного выбора адаптера.
