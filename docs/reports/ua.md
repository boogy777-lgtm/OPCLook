## Не скомпилировано на Linux / риски для Windows-сборки
- Ветка `cfg(windows)` функции `mdns::discover` (теперь возвращает `MdnsOutcome`): правка тривиальна, но CI не прогонялся.
- Windows-часть `mdns.rs` (`windows_impl`) не менялась.
- i686: multi-thread runtime (2 потока) вместо current-thread — стоит проверить на стенде отсутствие регрессии по памяти
  стека потоков и по времени закрытия.
- `LazyLock` (std) в `trust.rs` — нужен Rust ≥ 1.80 (на стенде собирается).
- Два запущенных экземпляра приложения с общей папкой PKI могут после сбоя убрать аренду друг друга (`session-trusted.list`).
- Discovery-клиент (`build_discovery_client`) по-прежнему с `trust_server_certs(true)`: GetEndpoints идёт по каналу без
  шифрования и сертификата сервера не передаёт, поэтому в `trusted` ничего не пишет (проверено наблюдением содержимого
  `trusted` после живых тестов).
- Остались `expect("…")` с обоснованием в `io.rs` (6) и `discovery.rs` (1): это старый код, доказуемо безошибочный
  (`timeout_drain` возвращает `None` только при таймауте, а он обрабатывается раньше).

## Что передать другим потокам (`app`)
- Комбинированный поиск на стороне приложения опрашивает `localhost:4840` несколько раз — бэкенд теперь это не удваивает,
  но приложению стоит слать один `SearchUaNetwork`.
- Поле «LDS-хост»; глобальный флаг доверия сертификату в настройках (теперь он означает «на сессию» — подписи в UI
  стоит поправить); перечитывание дерева при переключении «Только переменные»; заметки поисков приходят как `Log` с
  id 0 и session 0.
- Сообщения бэкенда по-прежнему русские (A9, ⏸).

## Что стоит запомнить
- `client_handle` ≠ `monitored_item_id`: `delete_monitored_items`/`modify_monitored_items` принимают id сервера.
- Sample-сервер `async-opcua` на `CreateMonitoredItems` отдаёт Good даже для несуществующего узла; ошибка видна только
  в первом data change или в чтении атрибута.
- `ServerBuilder::build()` требует контекст tokio-рантайма (`rt.enter()`).
- Запускать cargo с `CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=line-tables-only CARGO_PROFILE_TEST_DEBUG=line-tables-only`
  (иначе тестовые бинарники ~6 ГБ и диск переполняется).
- Ошибку Connect должен отправлять хост после освобождения слота, а не задача подключения (иначе гонка с мгновенным повтором).
