## U15

- `App::search_ua_all` строит запросы функцией `ua_all_commands`: LDS/mDNS (если выбран адаптер
  или задан LDS-хост) + **один** `FindServers` на `127.0.0.1:4840` (`localhost` — тот же адрес).
- Поле «LDS-хост» на вкладке OPC UA: `host[:port]` (`[::1]:4850`, префикс `opc.tcp://` и `/`
  допускаются), порт 4840 по умолчанию; хранится в `settings.json` (`ua_lds_host`, старые файлы
  читаются), восстанавливается при открытии диалога; Enter в поле запускает поиск. Неверный текст
  — локализованная ошибка в диалоге, поиск не запускается.
- Бэкенд: `SearchUaNetwork { bind, lds: Option<LdsTarget> }`; `LdsTarget { host, port, bind }` со
  своей привязкой (loopback для локального хоста, адаптер для удалённого). С заданным LDS спрашивается
  **только он** вместо стандартных локальных адресов; mDNS — как раньше, если выбран адаптер; без
  адаптера и без LDS — прежняя ошибка «Выберите сетевой адаптер»; без адаптера, но с LDS-хостом —
  спрашивается только LDS. Удалённый (не loopback) LDS-хост без адаптера — «Выберите сетевой адаптер».
- PNG диалога (headless, egui_kittest + wgpu/GL): `docs/reports/rest-u15-lds-{ru,en,zh}.png`.

## U13

Подпись: «Доверять сертификату сервера (только на эту сессию)» / «Trust the server certificate
(this session only)» / «信任服务器证书（仅本次会话）»; подсказка: действует только на это подключение,
сертификат не сохраняется навсегда, срок действия/имя хоста/ApplicationUri не проверяются, для постоянного
доверия — PKI-хранилище. Ошибка «сертификат не доверенный» цитирует подпись дословно (тест).

## F1 — нестабильный тест на Windows

Проверено:
- 8 прогонов `cargo test --test '*'` под `taskset -c 0,1` (по 4 при `--test-threads 1` и 8) на
  коде **до** исправления: 0 падений — на Linux не воспроизвелось.
- Каждый из 126 UI-тестов запущен по отдельности с `APPDATA`/рабочим каталогом во временной папке:
  один тест (`rejected_ua_connect_keeps_popup_open_with_error`) сохранял настройки без блокировки,
  четыре (`a7_toolbar_connect_reconnects…`, `connect_dialog_reopen_keeps_merged_subnet_scan_results`,
  `connect_dialog_ua_empty_host_without_adapter_searches_loopback_only`,
  `ua_subnet_scan_commands_are_not_pending_requests`) создавали `opcda-egui/pki`. Блокированные тесты
  переключали процессный `APPDATA` через `set_var`, и «чужой» `save()` попадал в каталог другого
  теста: тест, читающий настройки после своего `save()`, мог прочитать файл, перезаписанный чужим
  `save()` (последний писавший побеждает) — это объясняет «упало, повтор зелёный», но на Linux не
  воспроизвелось.
- Гонка создания ключевой пары: 8 клиентов одновременно на пустом PKI-хранилище → 7 сообщений
  «Certificate creation failed … already exists» и «Client is missing its application instance
  certificate» (воспроизведено тестом без замка). Первый прогон CI на чистом чекауте — ровно такой
  случай; повтор (файлы уже есть) проходил.
- Пороги времени: `gateway_shutdown` (< 5 с), `on_exit` (< 6 с) при таймауте воркеров 10 с, `ua_refresh_speed`
  (live, ignored) — оставлены: штатно завершение мгновенное, порог ловит только зависание.

Исправлено:
- `settings::thread_dir`: настройки теста — в каталоге **потока** (ставится `App::new_test` и
  `with_settings_lock`), без процессной блокировки и `set_var`. Приложение не ставит его, `app_dir()`
  читает `%APPDATA%` как раньше.
- `bff::ua::use_private_pki_dir`: PKI-хранилище процесса тестов — временный каталог (`App::new_test`);
  приложение не вызывает. В рабочей папке больше не появляется `opcda-egui/` (проверено после гейта).
- `session::build_client`: создание клиента — под замком. Это касается и приложения (комбинированный
  поиск запускает несколько клиентов сразу).
- Регрессионные тесты: `tests/test_isolation.rs` (sentinel-`APPDATA` остаётся пустым, `pki` в cwd не
  появляется, 8 потоков с разными языками не видят чужой файл) и `build_client_tests` (падает без замка).
- Контрольные прогоны после исправления — см. «Контроль» ниже.

## Решения в неоговорённом

- Формат LDS-хоста — одно поле `host[:порт]`, а не два.
- С заданным LDS-хостом стандартные локальные адреса LDS не опрашиваются (иначе поле «добавляло» бы
  хост, а не выбирало его); mDNS идёт как раньше.
- Комбинированный поиск при заданном LDS-хосте опрашивает его тоже (одно поле на все сетевые поиски).
- `DataValue::bad` принимает `BackendMsg`; общий `Display` — английский.

## Риски для Windows

- Windows-код A9 не компилировался (см. выше).
- `use_private_pki_dir` вызывается из `App::new_test`; если на Windows UI-тест будет ожидать клиентский
  сертификат в `%APPDATA%\opcda-egui\pki` — его там уже нет (в тестах такого ожидания не найдено).
- `build_client` — глобальный замок: первый клиент на чистом хранилище генерирует RSA-ключ (секунды в debug),
  остальные ждут (раньше генерировали параллельно и впустую).
- Не менялось: клиент обнаружения создаётся с `trust_server_certs(true)` — найденные при поиске
  сертификаты серверов остаются в общем `trusted` (см. `docs/status.md`).
