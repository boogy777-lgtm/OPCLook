## Решения в неоговорённом поведении

- **U9.** Отмена диалога во время подключения обрывает ожидание и отключает сессию (`reconnect = Stopped`), вкладка остаётся. Неудачная попытка из диалога
  останавливает фоновый автоповтор (решает пользователь). Если контейнер с тем же адресом уже есть и отключён — диалог переподключает его, а не создаёт дубль.
  `Connected` закрывает диалог только для той сессии, которую он ждёт.
- **U13.** Флаг доверия в диалоге всегда стартует выключенным; унаследованный глобальный флаг в `settings.json` читается (совместимость), но игнорируется.
- **A2.** Нечитаемый (не «нет файла») `settings.json` никогда не перезаписывается — сохранение блокируется до перезапуска, в журнал пишется причина.
- **K1.** Лимит запроса = max(настройка «таймаут операции», 5 с); Connect/Discover/поиск серверов — не менее 45 с. `Disconnect`, `ConfigureUaSubscription`,
  `Add`/`Remove`/`UaRuntime` истекают молча (бэкенд отвечает на них не всегда). Старый блок `ReadTimeout` в `tick()` убран (дублировал бы сообщение).
  Для `Write` просроченный запрос превращается в `Wrote{Err}` по ключу строки, для `AddItems` — строки выходят из состояния ожидания с «Bad».
- **A8.** Таблица остаётся общей для всех серверов (колонка «Сервер»), фильтра по вкладке нет; выбран «честный» вариант: подпись + убраны пункты дерева.
- **A7.** Кнопка при активной *отключённой* сессии переподключает её; в остальных случаях (нет сессий, подключена, подключается) открывает диалог.
- **CSV.** Подстрока допускается только как запасной вариант и только если совпадение единственное; неоднозначное имя — ошибка строки в журнале.

## Риски

- Сгруппированный коммит `8319e34` крупный (≈2000 строк): откат отдельного пункта потребует ручного выделения.
- `tests/ui_interactions.rs`: после A7 тулбарная «Подключиться» всегда активна, тесты диалога теперь берут *последнюю* активную кнопку с этой подписью
  (кнопка диалога рисуется позже тулбарной); изменение порядка отрисовки сломает эти тесты.
- K1: после истечения `Connect` сессия объявляется отключённой, но бэкенд может ещё завершить подключение; его запоздалый ответ отбрасывается
  (как неизвестный запрос), отдельный `Disconnect` бэкенду не отправляется — при следующем подключении/переподключении состояние бэкенда пересоздаётся.
- Трассировка K2 при включении быстро растит журнал (по строке на запрос и на ответ каждого опроса).
- Таймеры на Windows не проверялись (логика на `Instant`, платформонезависима).
