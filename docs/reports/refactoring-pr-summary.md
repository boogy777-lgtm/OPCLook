# PR draft: Share an Engine between GUI and headless CLI

The GUI previously combined session coordination, protocol access and presentation, making headless use and isolation difficult. This change introduces a shared Engine for the GUI and CLI, separates the contract, backend and locale, moves DA route preparation off the UI thread, and implements the A–H refactoring and B1–B20 fixes in the [status matrix](../refactoring-status.md).

The Engine owns request correlation, session scheduling and route leases. The GUI uses explicitly exported metadata and domain event handlers; the CLI supports typed JSON browse, read, write and watch. Windows helper IPC and route preparation have bounded waits, cancellation and typed failures. Settings preserve their flat serialized keys. Frame caches and journal virtualization reduce measured CPU time and requested bytes; the 100-update scene increases allocation count slightly. See the [measurement report](refactor-frame-baseline.md) for revisions, harness, conditions and results.

All workspace crates now require Rust 1.99, and CI and the toolchain file pin 1.99.1. On 1.99.1, formatting, Windows i686 workspace all-targets typecheck (with test-only resource/manifest skips), and the two Linux route-service tests passed. The complete local Linux `scripts/check-linux.sh` passed for code `c5762583f96635b37bc8924295703fde9bdccc8b` (subsequent commits before the Rust baseline migration changed documentation only), including live sample UA, CLI subprocess and B15 proxy tests. Fresh GUI all-target check, normal GUI/CLI build and GUI test targets passed after clearing the GUI cache. Rust 1.95.0 checked Windows i686 workspace all-targets with `--locked --offline` and test-only resource/manifest skips. Five scenes were reviewed before F, after F and after H. See the [status matrix](../refactoring-status.md) for counts and prior CI runs. [PR #8 checks](https://github.com/boogy777-lgtm/OPCLook/pull/8/checks) show the final HEAD status; merge requires green checks on that exact HEAD.

Native Windows CI includes unit tests, but physical DA, UAC, the privileged helper and real routes require an external Windows setup. Unsolicited events do not encode connection epochs after reconnection.
