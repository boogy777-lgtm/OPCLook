# Forced SDK DA1 inactive reads: local fixture (O24/O25)

This private probe forces the client SDK to `SODAC_VERSION_OPC_DAV10A`, reconnects an empty group in connected/inactive state, registers the fixture item and verifies that the group remains inactive. It asks the SDK for Cache and Device reads, preserves each service/item result and sample, and checks `OPC_QUALITY_OUT_OF_SERVICE` for the inactive Cache sample and Good for the fixture's Device sample. Device quality is a fact from this fixture, not a rule that all devices return Good.

A forced-version getter by itself does not prove the actual path. The SDK-owned fixture request factory counts `syncCache` and `syncDevice` **separately** for `Fixture.DeviceValue`, excluding `syncMaxAge`, cyclic, asynchronous and all other items. After baselining (which absorbs item registration activity), each probe read must increment precisely its corresponding counter and leave the other unchanged. This server-side observation also distinguishes `IOPCSyncIO::Read` from the `IOPCSyncIO2::ReadMaxAge` path in the pinned SDK. Both fixture cache references are released after `entry->stop()` and before `entry->terminate()`.

Pinned SDK source [SODaCServer.h](https://github.com/SoftingIndustrial/OPC-Classic-SDK/blob/5130e763998189c822882434c43e6be2eb0174cf/development/core/src/include/SODaCServer.h#L100) exposes `forceOPCVersion` and the forced-version getter. [SODaCComGroup.cpp](https://github.com/SoftingIndustrial/OPC-Classic-SDK/blob/5130e763998189c822882434c43e6be2eb0174cf/development/core/src/SODaC/SODaCComGroup.cpp#L545) drops the `IOPCSyncIO2` interface under DA1 forcing; its [sync read](https://github.com/SoftingIndustrial/OPC-Classic-SDK/blob/5130e763998189c822882434c43e6be2eb0174cf/development/core/src/SODaC/SODaCComGroup.cpp#L2222) uses `IOPCSyncIO::Read` and maps max age to Cache/Device. On the server, [SODaSGroup.cpp](https://github.com/SoftingIndustrial/OPC-Classic-SDK/blob/5130e763998189c822882434c43e6be2eb0174cf/development/core/src/SODaS/SODaSGroup.cpp#L2047) maps source to request type, and [SODaSRequest.cpp](https://github.com/SoftingIndustrial/OPC-Classic-SDK/blob/5130e763998189c822882434c43e6be2eb0174cf/development/core/src/SODaS/SODaSRequest.cpp#L902) applies out-of-service quality only to inactive sync Cache in this path.

Run on Windows after building the SDK probe and fixture:

```text
python opclook/docs/testing/native-sdk/server-fixture/run-interop.py --server fixture-build/Release/opcl_da_server.exe --proxy fixture-build/Release/opcl_opcproxy.dll -- ./softing-build/Release/softing_core_probe.exe --live-da1-inactive
```

The actual Windows result and SDK cleanup remain pending CI. Linux `test-da1-inactive-source.py` compiles the actual control and driver against deterministic stubs, while `test-subscription-counters.py` exercises the actual fixture counter branch against stubs; neither is a real SDK/COM execution. This is a local SDK-forced client path against a newer fixture, **not** proof of compatibility with a physically DA1-only or remote server. It does not enable production Async or change the production version choice.
