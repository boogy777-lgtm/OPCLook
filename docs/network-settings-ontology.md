# Онтология и план: «Сетевые настройки»

**Статус:** реализовано 2026-10-26 (см. раздел 15).  
**Проект:** `opcda-egui`  
**Область:** кэш сетевых адаптеров, выбор адаптера и локального IP, диагностика, исправление подсветки dropdown и обновления IP.

## 1. Принятая модель

Список адаптеров — **часть общего `settings.json`**. Конфиг читается при старте программы.

Правила:

- при старте список берётся из `cached_adapters`;
- Windows автоматически **не опрашивается**;
- **«Обновить»** полностью заменяет список текущим инвентарём Windows и сохраняет его в JSON;
- если конфиг удалён — список пуст до нажатия «Обновить»;
- в dropdown попадают только **Up + есть пригодный адрес**;
- down/no-address в dropdown не показываются; причина пишется в журнал;
- нет автоматического выбора и нет fallback;
- loopback-операции работают без адаптера;
- remote UA/DA, subnet scan и LDS/mDNS требуют явного адаптера;
- существующие сессии не перепривязываются при смене адаптера;
- техническая диагностика пишется в журнал, а не в отдельные поля формы.

Кэш является снимком на момент последнего «Обновить». До обновления он может быть устаревшим — это осознанная плата за простую модель.

## 2. Сущности

| Сущность | Что это | Идентичность | Где живёт |
|---|---|---|---|
| `CachedAdapter` | Снимок адаптера для dropdown | `AdapterId` = GUID | `settings.json` |
| `Address` | IP, prefix, scope | `(AdapterId, IpAddr)` | внутри `CachedAdapter` |
| `Selection` | Явный выбор пользователя | `None \| Adapter(GUID)` | `settings.json` |
| `LocalIp` | Адрес-источник binding | `(AdapterId, IpAddr)` | settings + lease |
| `Lease` | Неизменяемый снимок для операции | `generation` | память |
| `JournalEvent` | Диагностическое событие | время + текст | журнал |

Связи:

```text
Settings
  ├── cached_adapters[] 1..N CachedAdapter
  │     └── addresses[] 1..N Address
  ├── preferred_adapter ──> AdapterId | None
  └── selected_local_ip ──> IpAddr | None

Selection + CachedAdapter
  └── Lease
        ├── UA NetworkBinding
        ├── SubnetSpec
        └── DA RoutePlan
```

Инварианты:

- `AdapterId` уникален;
- `UNSPECIFIED` не участвует в выборе;
- loopback не показывается как обычный адаптер;
- ровно одна строка dropdown может быть выбрана;
- stale GUID означает «не выбран», а не первую карту списка;
- `selected_local_ip` обязан принадлежать выбранному адаптеру;
- down-адаптер не становится рабочим выбором;
- активные сессии сохраняют старый binding;
- отсутствие конфига не запускает автоматический опрос Windows.

## 3. Формат `settings.json`

```json
{
  "preferred_adapter": "5aa476f1-3809-11f0-94bb-806e6f6e6963",
  "selected_local_ip": "172.28.76.90",
  "cached_adapters": [
    {
      "id": "14693899-fe86-4f25-a6d6-814e60291d39",
      "name": "Wi-Fi",
      "description": "Intel(R) Wi-Fi 6E AX211 160MHz",
      "state": "up",
      "addresses": [
        { "ip": "172.28.76.90", "prefix": 24, "scope_id": null }
      ],
      "gateways": ["172.28.76.1"],
      "if_index": 3,
      "ipv6_if_index": 3,
      "luid": 123,
      "metric": 25,
      "is_physical": true
    }
  ]
}
```

Требования к формату:

- `cached_adapters` — сериализуемый снимок только пригодных адаптеров;
- для отображения достаточно `id`, `name`, `is_physical`;
- для binding нужны `addresses`, `if_index`, `ipv6_if_index`, `luid`;
- для DA route нужны `gateways`, `addresses`, `luid`;
- `description` и `metric` хранятся для журнала/диагностики, но не выводятся в основной форме;
- отсутствие `cached_adapters` в старом JSON = пустой список;
- некорректные записи отбрасываются с записью в журнал;
- дубли `AdapterId` не создают несколько выбранных строк.

## 4. Онтология UI

### Остаётся в форме

| Поле | Смысл | Источник | Сценарий |
|---|---|---|---|
| **Сетевой адаптер** | Явный выбор одной карты | `cached_adapters` + `preferred_adapter` | UA remote, subnet, LDS/mDNS, DA remote |
| **Обновить** | Полностью перестроить кэш из Windows | `GetAdaptersAddresses` | Воткнули кабель, включили VPN, сменили IP |
| **Локальный IP** | Адрес-источник binding | выбранный `CachedAdapter` | UA binding, subnet, DA route |
| **Статус/hint** | Короткое действие или причина | состояние выбора | «Не выбран», «Нажмите Обновить», «Сохранённый адаптер недоступен» |
| **Забыть** | Удалить stale GUID/IP | `preferred_adapter` | Сохранённый адаптер исчез |
| **Закрыть** | Закрыть окно | — | Изменения уже сохранены |

Допустимая компактная форма:

```text
Сетевой адаптер: [ Wi-Fi (физический) ▼ ] [Обновить]

Локальный IP: 172.28.76.90/24
Выбор применяется сразу.

[Закрыть]
```

Если IP несколько:

```text
Локальный IP: [ 172.28.76.90/24 ▼ ]
```

Если выбор stale:

```text
Сетевой адаптер: [ Не выбран ▼ ] [Обновить]
Сохранённый адаптер недоступен. Выберите активный.
[Забыть]
```

Если кэш пуст:

```text
Сетевой адаптер: [ Не выбран ▼ ] [Обновить]
Список не загружен. Нажмите «Обновить».
```

### Удаляется из формы → журнал

| Поле | Причина |
|---|---|
| Заголовок «Сетевые адаптеры» | Дублирует «Сетевой адаптер» |
| «Описание» | Диагностика; нужно только для различения имён |
| «Состояние» | В dropdown только Up; down пишется в журнал |
| «Адреса» (полный список) | Диагностика; в UI достаточно выбранного IP |
| «Шлюз» | Нужен только DA route |
| «Метрика» | Не участвует в выборе |
| «Используется» | Дублирует выбранный адаптер/IP |
| «Маршрут DA» | Относится к DA, а не к выбору карты |
| Сырая «Ошибка сети» | Полный текст в журнал, в UI только действие |

## 5. Сценарии

| Сценарий | Поведение |
|---|---|
| UA loopback | Адаптер не нужен; используется loopback binding |
| UA remote host / connect | Нужен выбранный адаптер и IP |
| UA subnet scan | Нужен lease; subnet из выбранного IP/prefix |
| LDS/mDNS | Нужен выбранный адаптер; LDS не обязателен |
| DA local | Адаптер и helper не нужны |
| DA remote | Нужен адаптер; host-route через helper; шлюз из адаптера |
| Wi-Fi + Ethernet + VPN/VMware | Ручной выбор; в dropdown имя + тип |
| Адаптер down | Не показывается в dropdown; событие в журнале |
| Сохранённый адаптер исчез | «Не выбран», статус, «Забыть» |
| Несколько IP | ComboBox только с адресами выбранного адаптера |
| Нет пригодного адаптера | Loopback доступен; remote/subnet/LDS — ошибка |
| Смена адаптера при активной сессии | Старая сессия не перепривязывается |
| Удалён конфиг | Пустой список до «Обновить» |
| Перезапуск с конфигом | Список и выбор из `cached_adapters` |

## 6. Логика выбора

### Startup

1. `Settings::load()` читает JSON.
2. `NetworkState` заполняется из `cached_adapters`.
3. Windows не опрашивается.
4. Если `preferred_adapter` найден в кэше — он выбран.
5. Если не найден — выбранной строки нет, статус «Сохранённый адаптер недоступен».
6. `selected_local_ip` проверяется на принадлежность выбранному адаптеру. Чужой IP не сохраняется и заменяется первым пригодным.

### «Обновить»

1. `GetAdaptersAddresses`.
2. Отбросить loopback.
3. Отбросить `!is_usable()` (down/no address).
4. Полностью заменить `cached_adapters`, не мержить со старым списком.
5. Сохранить JSON.
6. Переразрешить `preferred_adapter`.
7. Нормализовать `selected_local_ip`.
8. Записать в журнал полный список, включая пропущенные down/no-address.
9. Перерисовать форму.

Если инвентарь получить не удалось:

- старый кэш не затирается;
- ошибка пишется в журнал;
- в UI короткий статус «Не удалось обновить список».

### Выбор адаптера

1. Найти `CachedAdapter` по GUID.
2. Если адаптера нет — stale-статус, без fallback.
3. Выбрать локальный IP:
   - если сохранённый IP принадлежит адаптеру — оставить;
   - иначе первый пригодный.
4. Сохранить `preferred_adapter` и `selected_local_ip`.
5. Разрешить lease из кэша.
6. Записать выбор, IP, binding и lease в журнал.
7. Запросить repaint.

### Смена IP

- ComboBox содержит только адреса выбранного адаптера;
- при одном адресе — read-only;
- при смене IP сохранить настройку и переразрешить lease;
- subnet и binding меняются вместе с IP;
- старый IP не остаётся в настройках.

## 7. Исправление двух дефектов

### 7.1. Все строки dropdown синие

Возможные причины:

1. несколько `CachedAdapter` имеют одинаковый `AdapterId`;
2. сохранённый GUID отсутствует, но UI показывает не «Не выбран», а первый адаптер;
3. визуальный баг egui/темы, а не состояние выбора.

Порядок исправления:

1. Добавить тест уникальности `AdapterId`.
2. При дублях/`UNSPECIFIED` не показывать неоднозначный список; записать ошибку в журнал; исправить источник GUID.
3. В UI вычислять `selected` явно:
   ```text
   selected = preferred.adapter_id() == Some(adapter.id)
   ```
4. Показывать видимый маркер выбора (radio/галочка), не полагаться только на синий фон.
5. Stale GUID: `selected_text = «Не выбран»`, ни одна строка не выбрана.
6. UI-тест: ровно одна selected-строка; stale GUID — ноль selected.

Подсветку нельзя «лечить» сменой цвета без проверки уникальности ID и состояния выбора.

### 7.2. Локальный IP не перечитывается

Причины:

- UI берёт IP из старого глобального `selected_local_ip`;
- при одном адресе строка IP вообще не рисуется;
- IP принадлежит другому адаптеру;
- down-адаптер не даёт lease, но UI не объясняет причину;
- старая ошибка не очищается после успешного выбора.

Исправление:

- всегда показывать IP для выбранного адаптера;
- источник — выбранный адаптер/lease, а не произвольное поле;
- при смене адаптера сбрасывать старый IP;
- при одном адресе — read-only;
- при нескольких — ComboBox;
- при отсутствии IP — «Нет IP», remote-операции блокируются;
- успешный resolve очищает старую ошибку;
- тест «выбор Ethernet → IP Ethernet, выбор Wi-Fi → IP Wi-Fi».

## 8. Диагностика в журнале

В журнал писать:

- загрузку кэша при старте: количество, GUID, имена;
- каждый Refresh: старт/финиш, число адаптеров;
- каждого кандидата: GUID, имя, описание, state, addresses/prefix/scope, gateways, metric, type;
- пропуск down/no-address с причиной;
- выбранный адаптер, IP, binding, lease;
- stale GUID и ошибки инвентаря;
- смену IP;
- DA route status/error.

В UI не выводить `description`, `state`, полный список адресов, `gateway`, `metric`, `used`, `DA route`, сырой `NetError`. В UI остаётся только короткий локализованный статус.

## 9. Что убрать из неявной логики

- Автоматический refresh при открытии вкладки.
- Неявный refresh из `current_network_binding`.
- Неявный refresh из `discover_da_all`.
- Неявный refresh из `prepare_da_route_for_host`.
- Любую попытку выбрать адаптер при отсутствии сохранённого GUID.

`GetAdaptersAddresses` вызывается **только** по кнопке «Обновить».

## 13. Критерии готовности

- Список адаптеров читается из `settings.json` при старте.
- Удаление конфига даёт пустой dropdown до «Обновить».
- «Обновить» полностью заменяет список и сохраняет JSON.
- Down/no-address отсутствуют в dropdown; причина в журнале.
- Все строки больше не выглядят выбранными; ровно одна или ноль.
- Stale GUID → «Не выбран», без fallback и без чужого IP.
- IP всегда принадлежит выбранному адаптеру и обновляется при смене.
- Один IP — read-only; несколько — ComboBox.
- Технические поля убраны из UI и пишутся в журнал.
- Активные сессии не перепривязываются.
- Тесты и `cargo check --all-targets` зелёные.

## 14. Риски и компромиссы

- Кэш может быть устаревшим до «Обновить»; это принято для простой модели.
- Адаптер, который был Up на момент Refresh, может стать Down до следующего Refresh.
- Если сохранённый GUID исчез, пользователь должен явно выбрать новый адаптер или нажать «Забыть».
- Down-адаптеры не показываются; если понадобится режим «показывать disabled», это отдельное решение.
- Кэш увеличивает `settings.json`; записи должны быть компактными и валидируемыми.
- Дубли `AdapterId` должны блокировать неоднозначный выбор, а не маскироваться подсветкой.

## 15. Состояние реализации (2026-10-26)

Реализовано в коде:

- `Settings::cached_adapters` (transparent JSON array) с поштучным отбрасыванием
  битых записей и диагностикой загрузки;
- `NetworkState::load_cache()` при старте без вызова
  `GetAdaptersAddresses`;
- `build_adapter_cache()` заменяет кэш, отбрасывает loopback, down, no-address,
  `UNSPECIFIED` и дубли GUID;
- `reconcile_selection()` даёт `Selected | NotSelected | Stale`, сохраняет IP
  только у выбранного адаптера и не делает fallback;
- `App::apply_network_inventory()` — единственный путь обновления после
  `inventory_adapters()` из кнопки «Обновить»; при ошибке старый кэш остаётся;
- минимальная форма: адаптер, «Обновить», локальный IP (read-only/ComboBox),
  короткий статус, «Забыть», «Закрыть»; технические детали — в журнал;
- dropdown строит уникальные строки, выбранная строка вычисляется явно из
  сохранённого GUID и помечается маркером «●»; stale GUID даёт ноль строк;
- `AdapterId` берётся из connection GUID (`AdapterName`), а не из
  `NetworkGuid` (network profile GUID может совпадать у нескольких адаптеров;
  именно это раньше давало дубли и пустой список после «Обновить»);
- смена адаптера/IP не перепривязывает существующие сессии: они сохраняют
  захваченный `ua_bind`/lease;
- неявные refresh удалены из `current_network_binding`, `discover_da_all`,
  `prepare_da_route_for_host`, старта subnet scan и открытия вкладки;
- журнал получает загрузку кэша, старт/финиш refresh, каждого кандидата,
  причины пропуска, выбор/IP/binding/lease, stale GUID, ошибки и DA route.

Тесты: `src/settings.rs`, `src/net.rs`, `tests/ui_interactions.rs` (109 UI
тестов, включая `network_tab_*`, `network_tab_refresh_button_queries_windows_inventory`,
`network_refresh_replaces_*`, `implicit_network_paths_do_not_refresh_inventory`,
`changing_adapter_does_not_rebind_active_sessions`).
